# Dataset A Profile (Part 19)

Generated by `scripts/profile_dataset.py` + ad-hoc per-app breakdowns this
session. Full machine-readable version: `profile_dataset_a.json`. Figures:
`figures/dataset_a_*.png`.

## Engineering Reasoning

I specifically required percentile statistics (p90/p95/p99), not just
mean/median, because an average can hide a rare but severe defect — which
is exactly what happened with `ms_since_last_event` (median 44ms looks
completely normal; the actual minimum is -713,900ms). The per-application
breakdowns for browser/keyboard/mouse/clipboard activity weren't in the
original profiling scope either; I added them because a single aggregate
"top applications" list doesn't tell you which *kind* of activity happens
where, and that distinction matters for judging which signals are even
observable per process.

## Applications

Top by active-time events: Google Chrome (118,134), Notepad (30,234),
Microsoft Word (5,365), Microsoft PowerPoint (3,234), Windows Explorer
(1,948), WindowsTerminal (1,687), Microsoft Excel (887). Figure:
`figures/dataset_a_top_applications.png`.

## Browser activity by application

`browser_click` and `browser_navigation` are Chrome-only by construction (L3
events only fire through the browser extension): 5,365 `browser_click` and
1,604 `browser_navigation` events, all attributed to Google Chrome, plus a
small number of `browser_navigation` events (36 Notepad, 29
WindowsTerminal, 23 Explorer, 20 Excel) that reflect the *active app at the
time* of a background browser navigation event, not navigation happening
inside those apps.

## Keyboard activity by application

`keystroke` events by active app: Google Chrome (29,912), Notepad (5,286),
Microsoft Word (1,568), Microsoft PowerPoint (1,362), WindowsTerminal
(315). Typing happens overwhelmingly in the browser (portal data entry) and
Notepad (scratch notes), consistent with the case-study sessions' app lists
(`chrome`, `excel`, `notepad` recur together).

## Mouse activity by application

`mouse_click` by active app: Google Chrome (6,008), WindowsTerminal (76),
procmine-desktop-agent (59), Microsoft Excel (19), Windows Explorer (6).
Overwhelmingly browser-driven, as expected for a portal-based workflow.

## Clipboard activity by application

`clipboard_change` by active app: Google Chrome (3,553), Notepad (1,412),
Microsoft Word (116), Microsoft PowerPoint (100), Microsoft Excel (7) — a
copy-from-portal, paste-into-Notepad/Excel/Word pattern is visible just
from the app distribution, consistent with `gt.jsonl`'s own
`clipboard_copy`/`clipboard_paste` records tying clipboard events to
specific case IDs.

## Screenshots

34,580 `screenshot_smart` events; only 2,489 (7.2%) resolve to an actual
JPEG on disk in this distribution of Dataset A (see
`data_quality_report.md` Part 10 for the Dataset B comparison — 81.2% there).

## Extracted text

4.48% of events (7,300/162,768) carry non-empty `extracted_text`, 86%
concentrated on `app_switch` events. Full detail:
`data_quality_report.md` Part 11.

## Temporal gaps

`ms_since_last_event`: median 44ms, mean 499.5ms, p90 882ms, p95 2,188ms,
p99 5,060ms, max ~2.4 hours (genuine idle period). Min is a real anomaly
(-713,900ms) tied to a chunk-boundary data-integrity issue — see
`data_quality_report.md` Part 6 and `debugging_log.md`.

## Ground truth profile (ties to ground_truth_validation.md)

2,009 executions across 63 sessions (~32/session), spanning ~8-10 distinct
process codes per session, with process variants and repeated executions of
the same process code the norm rather than the exception. Minimum
complexity observed: 24 executions in one session (no "simple" session
exists in Dataset A). Maximum: 44 executions in one session.
